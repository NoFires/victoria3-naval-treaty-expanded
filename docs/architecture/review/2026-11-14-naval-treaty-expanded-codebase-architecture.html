Separation of Concerns

Risk
Journal Entry serves as UI, global scheduler, and lifecycle authority

common/journal_entries/nte_journal.txt:175-251 couples player-facing UI presentation (map coloring, progress bars, buttons) with the global treaty monthly scheduler (nte_global_treaty_monthly_pulse) and treaty collapse triggers (outcome). Moving the global pulse to on_monthly_pulse_country or a context = none global Journal Entry decouples simulation ticks from individual country UI instances.

Concern
Presentation strings and domain thresholds drift apart

Localization promises -20% naval upkeep (nte_l_english.yml:78) while global_naval_limitation_union_bonus grants -10% (nte_modifiers.txt:6); nte_btn_submarine_protocol_desc advertises 25 influence while nte_scripted_buttons.txt:390 gates on influence >= 50; nte_bilateral.20.e_tt promises +15 relations missing from events/nte_bilateral_treaty_events.txt:330-344.

Strength
Tonnage and fiscal formulas are cleanly isolated in script_values

All ship scoring, locked-tier caps, vote weights, and fiscal distress multipliers live in common/script_values/nte_ship_values.txt:1-307 rather than being duplicated inline across treaty articles and events.

Cohesion and Coupling

Risk
Monolithic 1,167-line nte_effects.txt combines four distinct domains

common/scripted_effects/nte_effects.txt:1-1167 mixes modifier cleanup utilities, locked-tier assignment, global multilateral pulse/voting, and bilateral enforcement/monthly checks in one file, making targeted edits error-prone and obscuring dependencies.

Concern
Fragile UI coupling to external mod localization key

gui/zz_nte_frontend_dlc.gui:23 detects Iron & Steam: Naval Overhaul via Not( EqualTo_string( Localize( 'je_naval_arms_race' ), 'je_naval_arms_race' ) ) while replacing all of types dlc_types, tightly coupling NTE's frontend GUI to both vanilla GUI internals and an external mod's localization key.

Concern
Duplicate comment numbering and mixed cleanup patterns

nte_effects.txt:830,847 repeats section marker # 5. and nte_global_on_withdrawal omits clearing transient threat markers cleanly until the following monthly pulse.

Layered Architecture

Risk
Presentation layer mutates authoritative treaty state directly

common/scripted_buttons/nte_scripted_buttons.txt:299-301,395-397 and events/nte_global_treaty_events.txt:524-526,640-642 add progress directly to root's Journal Entry progress bar instead of routing through a centralized domain effect on a global stability variable.

Strength
Treaty articles delegate lifecycle logic to scripted effects

Both global_naval_limitation_treaty.txt and bilateral_naval_limitation_treaty.txt keep lifecycle callbacks concise by delegating to named scripted effects rather than embedding hundreds of lines of imperative mutations inside treaty definitions.

Hexagonal Architecture / Ports and Adapters

Strength
Adaptive threshold port for Iron & Steam: Naval Overhaul

common/on_actions/zz_nte_overhaul_compat.txt:1-29 and nte_effects.txt:588-605 adapt qualitative super-heavy thresholds (7500/750 vs 5500/550) behind global_var:nte_naval_overhaul_detected without taking a hard dependency on external mod files.

Concern
Missing anti-corruption adapter for custom ship classes

nte_single_ship_effective_tonnage (nte_ship_values.txt:5-116) switches directly on vanilla ship type identifiers (ship_type_dreadnought, ship_type_carrier, etc.) and falls back to flat 20 / 6 base tonnage for any modded ship hull, leaving Naval Overhaul or custom ship mods under-scored on base hull value.

Risk
Full vanilla GUI overwrite instead of additive adaptation

gui/zz_nte_frontend_dlc.gui:1-69 replaces vanilla frontend_dlc.gui dlc_types wholesale instead of isolating compatibility metadata, creating immediate conflict risk with vanilla UI updates or other DLC-bar mods.

Scalability

Concern
Repeated live ship iteration inside AI acceptance and possible triggers

nte_country_effective_tonnage iterates every_scope_ship on every invocation. In global_naval_limitation_treaty.txt:348,355,361, it is evaluated three times per AI diplomatic acceptance check, and again inside bilateral_naval_limitation_treaty.txt:24 possible predicates across all country pairs, degrading late-game tick performance when fleets scale.

Concern
Fixed 5-seat rank ladder limits scaling beyond five major naval powers

nte_assign_locked_tiers (nte_effects.txt:55-229) tracks explicit variables gnl_rank1_country through gnl_rank5_country, capping explicit UI display and tiered recognition at 5 ranked seats even in multipolar late-game coalitions.

Observability

Risk
Vacant rank tooltip access generates continuous error.log spam

global_naval_limitation_union_desc (nte_l_english.yml:5, nte_l_simp_chinese.yml:6) directly dereferences Scope.GetGlobalVariable('gnl_rank3_country').GetCountry.GetName through gnl_rank5_country without existence checks, causing Paradox engine errors whenever fewer than 5 signatories exist.

Concern
Stability progress bar hides positive vs negative drift drivers

common/scripted_progress_bars/nte_bars.txt:14-22 uses plain if logic inside yearly_progress instead of vanilla progress_condition blocks, hiding the per-factor Advance/Retreat tooltip breakdown from players.

Strength
Transparent multi-factor AI acceptance descriptions

Both treaty articles expose detailed desc breakdowns (NTE_ACCEPTANCE_*) covering fiscal pressure, tonnage ratio, rivalry, alliance, and naval laws.

Security

Risk
Gameplay economy exploit via flat +2,000 minting on hull scrapping

nte_btn_scrap_obsolete_hulls (common/scripted_buttons/nte_scripted_buttons.txt:364-370) awards a flat country_minting_add = 2000 regardless of nation GDP or fleet size, enabling small or bankrupt nations to abuse scrapping cycles as an artificial treasury generator.

Concern
Hardcoded unrelated Steam ID and save-compatibility flag in virtual DLC

dlc/dlc_nte_overhaul/dlc_nte_overhaul.dlc:3,8 sets steam_id = 529340 (Victoria 3 Voice of the People / Paradox ID collision) and affects_save_compatibility = yes, creating unnecessary save-load friction when toggling compatibility patches.

Reliability

Risk
Swapped directed scopes in bilateral treaty visible/possible checks

Per Victoria 3 treaty_articles.md:408-433, for kind = directed articles root is the prospective source_country (restricted party) and scope:other_country is the prospective target_country (enforcer). bilateral_naval_limitation_treaty.txt:16-30 checks country_rank >= rank_value:major_power on root and nte_country_effective_tonnage > 0 on scope:other_country, inverting enforcer and restricted-party prerequisites.

Risk
Missing once_per_treaty, offer AI usage, and renegotiation guards

Unlike vanilla mutual articles (00_alliance.txt, 01_defensive_pact.txt), global_naval_limitation_treaty.txt omits usage_limit = once_per_treaty, article_ai_usage = { offer }, and is_renegotiation checks in can_ratify (same renegotiation gap in bilateral_naval_limitation_treaty.txt).

Risk
Global treaty dissolution cascade on single-chair withdrawal

Because global_naval_limitation_treaty.txt:93 restricts new membership signing exclusively to global_gnl_chair_country and on_break fires alongside on_withdrawal (treaty_articles.md:134), a chair withdrawal or break immediately triggers treaty-wide dissolution or breaks hub-and-spoke bilateral links without a transition grace window.

Risk
Bilateral war-enforced expiry race and post-break modifier leak

nte_bilateral_enforced_by_war expires in months = 1 (bilateral_naval_limitation_treaty.txt:89) while nte_bilateral.20 has duration = 2 months, risking unwarranted +3 infamy/-50 influence penalties if confirmed after 30 days. Additionally, nte_bilateral.2.a applies nte_bilateral_capital_slowdown even after nte_bilateral_on_break_handler already cleaned up the treaty.

Resilience

Concern
Reactive-only Naval Overhaul detection misses pre-built fleets

zz_nte_overhaul_compat.txt:1-29 only sets global_var:nte_naval_overhaul_detected inside naval_overhaul_on_ship_constructed; if no ship finishes construction after game start or mid-save load, Naval Overhaul detection remains unset and super-heavy checks apply the lower vanilla 5500/550 threshold.

Concern
Super-heavy breach triggers indefinite penalty loop on opt-in

nte_global_treaty_events.txt:497-557 (nte_global.8) gives non-chair members no clean compliance exit when retaining a super-heavy hull; monthly checks keep re-evaluating breach/escalation without clear remediation tracking.

Strength
Recovery fallback prevents orphaned treaties if chair vanishes

nte_journal.txt:189-221 checks whether global_gnl_chair_country still exists and participates, promoting a successor or dissolving gracefully—though this belongs in on_actions rather than per-country JE pulses.

Data Architecture

Risk
No single source of truth (SSOT) for global treaty stability

Treaty stability lives independently inside each member country's nte_treaty_stability_bar on je:global_naval_limitation_union. Multiple buttons (nte_scripted_buttons.txt:299,395) and events (nte_global.8.a, nte_global.10.b) mutate only root's bar, causing per-country divergence and premature single-member collapse.

Concern
Global Journal Entry group key naming mismatch

common/journal_entry_groups/NTE_journal_entry_groups.txt:1 defines global_naval_limitation_union_group without an illustration or matching je_group_global_naval_limitation_union_group localization key (currently localized under bare global_naval_limitation_union_group).

Cost Efficiency (FinOps)

Concern
Simulation CPU cost from uncached ship-loop evaluations

Cloud FinOps does not apply to a local Paradox mod, but engine CPU budget is impacted by repeated live every_scope_ship traversals in AI scoring (global_naval_limitation_treaty.txt:348-361) instead of reading a monthly cached nte_cached_tonnage variable.

Operability

Concern
No automated build or verification scripts in repository

AGENTS.md mandates UTF-8 BOM preservation, balanced braces {}, valid JSON metadata, and 100% EN/ZH key parity, but no repository script automates these checks prior to workshop packaging.

Concern
Metadata missing explicit mod id

.metadata/metadata.json omits an explicit "id": "naval_treaty_expanded" field, relying solely on display name and workshop packaging metadata.

Deployment Architecture

Strength
Clean mod folder separation and ignore hygiene

.gitignore excludes .dsh/, editor folders, and logs, and AGENTS.md documents exact Workshop upload boundaries (.metadata, common, dlc, events, gui, localization, thumbnail.png).

Concern
Virtual DLC save-compatibility flag complicates mid-campaign toggling

dlc/dlc_nte_overhaul/dlc_nte_overhaul.dlc:8 marks affects_save_compatibility = yes even though it functions strictly as a compatibility indicator badge.

Event Architecture

Risk
Quinquennial conference fan-out lacks two-stage aggregation

nte_global.7 (events/nte_global_treaty_events.txt:410-495) is dispatched simultaneously to every member; choosing option b immediately applies -2 stability per respondent (and mutates gnl_tonnage_base_limit globally if Chair vs +20% Escalator if non-Chair), creating N-fold stability spikes and asymmetric behavior.

Risk
Vote countdown race and unbounded isolation sanction spam

nte_effects.txt:741-775 decrements gnl_voting_months_left and gnl_isolation_months_left inside the same monthly tick as proposal creation, shortening effective voting time and lacking an isolation cooldown or ally exclusion (nte_scripted_buttons.txt:77-152).

Concern
on_break fires in addition to on_withdrawal in Paradox engine

Per treaty_articles.md:134, on_break executes in addition to on_withdrawal. global_naval_limitation_treaty.txt routes both to nte_global_on_withdrawal, executing cleanup/dissolution logic twice on treaty break unless separated cleanly.

AI Architecture

Concern
LLM AI criteria N/A; scripted diplomatic AI has quota-prediction mismatch

The codebase contains no LLM/ML pipelines. For Victoria 3's scripted AI, global_naval_limitation_treaty.txt:346-352 assumes Great Powers receive a 1.67x baseline cap in inherent_accept_score even when Ranks 1–2 are already locked, causing latecomer Great Powers to miscalculate their post-ratification quota and breach immediately upon joining.

Concern
Bilateral restriction and AI strategy gap

common/ai_strategies/zz_nte_ai_strategy.txt:1-49 adjusts wanted_navy_size for multilateral flags (nte_over_limit_flag, nte_near_limit_flag, nte_sanctioned_flag) but ignores nte_bilateral_restricted_flag and nte_bilateral_near_limit_flag, and isolation vote AI base score lacks zero-baseline gating against allies.

Strength
Non-destructive AI strategy injection and fiscal pressure model

zz_nte_ai_strategy.txt uses INJECT:ai_strategy_default cleanly and nte_naval_fiscal_pressure_index combines naval budget share, deficits, and scaled_gold_reserves realistically.

Multi-Tenancy

Risk
GetPlayer localization dependency leaks single-player bias in multiplayer/observer

global_naval_limitation_union_desc (nte_l_english.yml:5, nte_l_simp_chinese.yml:6) uses GetPlayer instead of JournalEntry.GetCountry / ROOT.GetCountry, displaying the local client player's tier/tonnage or failing in observer mode.

Strength
Deterministic single-chair global settlement for multiplayer sync

Executing global treaty resolution strictly on global_var:global_gnl_chair_country prevents non-deterministic multi-client ordering divergence (multiplayer_synchronized: true).

Architecture Governance

Strength
Explicit engineering constraints documented in AGENTS.md

AGENTS.md establishes clear rules for vanilla reverse-engineering before scripting, prefix isolation (nte_/gnl_), zero error.log tolerance, multiplayer determinism, and EN/ZH localization parity.

Concern
Implementation has drifted from AGENTS.md invariants in GUI and error.log guards

gui/zz_nte_frontend_dlc.gui overrides a full vanilla GUI type block despite incremental-injection guidance, and unguarded gnl_rank3..5_country loc references plus GetPlayer violate zero-error.log / multiplayer hygiene.

Domain Architecture

Strength
Clear bounded separation between Multilateral Union and Bilateral Coercion

The domain cleanly distinguishes cooperative multilateral arms control (global_naval_limitation_treaty, gnl_*) from asymmetric post-war bilateral limitation (bilateral_naval_limitation_treaty, nte_bilateral_*).

Concern
Bilateral formal break and ongoing monthly breach share a single resolution event

nte_bilateral.2.a conflates monthly over-limit compliance warnings (where the treaty remains active) with formal on_break events (where nte_bilateral_on_end_clean already terminated the treaty).

API Architecture

Concern
Engine contract mismatches on treaty callbacks and directed scopes

Violations of Victoria 3 1.15.1 treaty article contracts—specifically on_break additive execution over on_withdrawal, kind = directed root vs scope:other_country semantics, and missing once_per_treaty / is_renegotiation checks—create subtle runtime bugs.

Architecture Fitness Metrics

Concern
No automated architectural fitness checks

Checks for UTF-8 BOM, balanced braces {}, localization key parity (ZH_ONLY=0, EN_ONLY=0), and cross-file modifier/variable reference integrity are all manual rather than automated.

Common Anti-Patterns

Risk
Big Ball of Mud / God Module in nte_effects.txt

At 1,167 lines spanning 4 unrelated responsibilities, common/scripted_effects/nte_effects.txt exhibits classic God Module traits, increasing merge conflict and regression risk.

Risk
Shared Mutable UI State Acting as Source of Truth

Each signatory's nte_treaty_stability_bar acts as an uncoordinated mutable store updated inconsistently by buttons and events rather than deriving from global_var:gnl_treaty_stability.

Testability

Concern
No standalone validation or deterministic smoke harness

Static correctness (BOM, brace balance, JSON validity, loc key parity) and script-level invariants are not exercised by an automated test script; testing currently relies entirely on launching Victoria 3 and inspecting error.log.

Evolvability

Strength
Clean namespace discipline eases extension and conflict isolation

Strict nte_* / gnl_* prefixing and modular alert/modifier/button files make adding new treaty protocols straightforward once nte_effects.txt is split.

Concern
GUI full-type overwrite blocks safe vanilla patch upgrades

Replacing all of dlc_types in gui/zz_nte_frontend_dlc.gui forces manual diffing on every Victoria 3 UI patch.

Architectural Smells

Risk
God Service (nte_effects.txt) and Smart UI (nte_journal.txt)

nte_journal.txt hosts the global monthly scheduler inside a UI Journal Entry, while nte_effects.txt centralizes four unrelated domains in a single 1,167-line file. Combined with direct UI progress-bar mutations in buttons/events, domain invariants are difficult to reason about in isolation.
